# 象棋界面复刻 · 参考图设计元素分析

> 参考图：`clipboard-2026-09-25T19-32-53-207Z-9946de48.jpg`（864 × 1920，竖屏手机截图）
> 分析方法：用 `sharp` 读原始像素，做边界扫描 / 色带聚类 / 笔刷采样，**所有数值均为实测**，不是目测。
> 前置约束（用户铁律）：**一切改动以手机端体验为准**；不引入构建步骤、不引框架、不加外部依赖。

## 一、参考图实测几何

用「琥珀色像素列/行聚类」定位棋子圆心，得到确定性数据：

| 量 | 实测值 | 推导 |
|---|---|---|
| 棋子列心（9 列） | 57, 150, 245, 337, 432, 527, 619, 713, 807 | 列距 **93.75px** |
| 棋子行心（10 行） | 549 → 1363 线性插值 | 行距 **90.44px** |
| 棋子直径 | ≈ 86px（宽 84–86） | **棋子/格距 = 86 / 93.75 = 0.917** |
| 棋盘石面左右边界 | x = 24 … 831（宽 807） | 左右留白 33 / 24px |
| 棋盘石面上下边界 | y = 490 … 1471（高 981） | 上下留白 59 / 108px |
| 网格横 8 格 × 纵 9 格 | 750 × 814px | 格宽:格高 = **1 : 1.085** |

**关键结论（直接影响现有代码）**

1. **参考图的棋盘不是 8:9，是接近 8:8.7（≈1:1.085 的格距比）。**
   现有代码 `.xq-board { aspect-ratio: 8 / 9 }` 把「格距比」和「棋盘外框比」混为一谈。
   正确做法：外框比例由 **9 行 × 8 列 + 上下留白**决定，而非硬写 8/9。
2. **棋子直径 = 格距的 0.917 倍**，几乎顶满格子。现有 `.xq-p` 是 `width: 9.6%`（= 格距的 0.768 倍），明显偏小 —— 手机上显得空、点击目标也偏小。
3. **上留白 ≠ 下留白**（59 vs 108）：底部多出的空间是给「红方帅位 + 玩家头像」的。这说明参考图的棋盘区**不是对称内边距**，硬套 `padding: 6%` 会失真。

## 二、实测配色

| 部位 | 实测 HEX | 说明 |
|---|---|---|
| 棋盘石面（亮部） | `#acb099` / `#a9ae98` | 灰绿石材，带轻微青调 |
| 棋盘石面（暗部） | `#8b9980` | 边缘受光衰减 |
| 网格线（亮） | `#b7baa5` | **线比底色只亮一点点**，是「刻痕」不是「描边」 |
| 网格线（暗槽） | `#7c816a` | 刻痕下沿的阴影 |
| 棋子面·琥珀 | `#f7d4aa` → `#ffdd9d` → `#ffe3a3` | 暖琥珀，中央偏亮（**径向渐变**） |
| 棋子面·高光 | `#ffeab0` | 右上方高光点 |
| 棋子侧面/厚度 | `#c9a56b` → `#a5924e` | 颜色更深、更饱和，模拟**圆盘厚度** |
| 棋子外圈金边 | `#ebd8b0` / `#fde2ac` | 亮金细边 |
| 棋子阴影 | `#47463d`（在 `#a9ae98` 底上） | 偏移阴影，非纯黑 |
| 页面背景（顶） | `#192f26` | 深墨绿 |
| 页面背景（底） | `#0f1f1d` | 更深的墨绿 |
| 按钮底 | `#688155`（含场景透色） | 半透明深色圆角块 |
| 按钮图标 | `#e8d9a4` 系（金） | 金色线性图标 |

**关键结论**

1. **棋盘是「浅灰绿石材」**，不是常见的木色，也不是现有代码的 `var(--bg-panel)` 冷灰。需要新增一组**象棋专属色令牌**。
2. 网格线**对比度极低**（`#b7baa5` vs `#acb099`，ΔL 约 3%）。现有代码用 `currentColor` + `--text-dim` 55% 透明，对比度反而**过高**，看起来像「网格纸」而不是「石刻棋盘」。
3. 棋子靠**三层栈叠**做立体感：外圈金边 + 琥珀径向渐变面 + 底部厚度色。纯 `border` + 单色 `background` 做不出来。

## 四、和现有实现的差距（必须先决策）

| 维度 | 参考图 | 现有 `index.html` |
|---|---|---|
| 玩法 | **自由对弈**（32 子全盘，双方各一玩家） | **残局闯关**（题库 104 题，黑方 AI 应手） |
| 信息区 | 上下两个玩家头像 + 场景 | 无头像，只有「第 N 关 · 出处」文字条 |
| 关卡选择 | 无（自由对弈不需要） | 分档 chips + 104 个关卡圆点 |
| 操作行 | 6 个：沙盘/悔棋/支招/翻转/重来/关闭AI | 3 个：提示/悔棋/重摆 |
| 棋子数 | 32 | 残局通常 4–12 |

### 决策：不换玩法，只换「皮」

理由（三条，按权重排）：

1. **玩法是产品的核心价值，视觉是外壳。** 现有 104 题题库经过 `tests/xiangqi-moves.test.js` 反向验算（难度标定 / 存在正解 / 判定耗时达标），换玩法等于把这份资产丢掉。用户的需求原话是「UI 视觉风格老旧、布局混乱」，指的是**观感**，不是玩法。
2. **参考图的 6 个按钮里有 3 个在残局模式下无意义**（沙盘、翻转、关闭AI 都是自由对弈概念）。硬加会做出死按钮 —— 死按钮比没有按钮更糟。
3. **手机屏幕上，信息密度必须取舍。** 参考图能塞下 32 子和两层头像，是因为它没有 104 个关卡的导航。硬塞会让 375px 宽的屏幕上每个可点元素都掉到 32px 以下，违反铁律。

### 因此本次改动范围

**保留**：玩法、题库、判定逻辑、关卡导航（chips + 圆点）、`xqTap`/`xqSelect`/`xqUndo` 全部交互逻辑 —— **一行 JS 逻辑都不动**。
**重做**：`.xq-*` 全部视觉层 +
- 棋盘改为石材底 + 刻痕网格 + 楚河汉界胶囊
- 棋子改为三层立体圆盘（金边 / 琥珀径向渐变 / 厚度阴影），尺寸提到格距的 0.90
- 操作行改为参考图那种「图标 + 标签」的横向按钮组，**只保留残局有意义的 3+2 个**（提示/悔棋/重摆 + 上一关/下一关）
- 顶部信息条改为「玩家卡」样式（金环头像位 + 关卡信息 + 手数）

**明确不做**（并在最后回报里说明）：
- 自由对弈模式、32 子开局、翻转棋盘、关闭 AI、沙盘
- 背景宫殿/灯笼/树木场景插画（需要位图素材，违反「零依赖」；用 CSS 渐变做一个**抽象氛围底**替代）

## 五、实现方案（纯 CSS + 极少量 JS）

### 5.1 新增象棋专属色令牌

放进 `:root`，**不污染全局主题**，命名前缀 `--xq-`：

```css
/* === 象棋盘专属配色（源自参考图实测，勿随手改） === */
--xq-stone:        #acb099;   /* 石面亮部 */
--xq-stone-dark:   #8b9980;   /* 石面暗部 / 边缘 */
--xq-groove:       #7c816a;   /* 刻痕阴影 */
--xq-groove-hi:    #b7baa5;   /* 刻痕受光 */
--xq-coin-face:    #ffe3a3;   /* 棋子面中心 */
--xq-coin-edge:    #e0bc82;   /* 棋子面外沿 */
--xq-coin-side:    #b8873f;   /* 棋子厚度（侧面） */
--xq-coin-rim:     #fde2ac;   /* 金色外圈 */
--xq-coin-shadow:  rgba(38, 46, 32, 0.45);
--xq-red-ink:      #a8231f;   /* 红方字色（实测量级，饱和度高于 --expense） */
--xq-black-ink:    #241a12;   /* 黑方字色（暖黑，不是 #000） */
```

**为什么用暖色墨**：参考图的黑子字是 `#241a12` 量级的暖黑，红子是 `#a8231f` 量级的朱砂红。现有代码用 `--text-primary`（冷灰）和 `--expense`（粉红 `#bd4c76`）—— 粉红用在记账支出上是对的，放在象棋上就是「贴纸感」。

### 5.2 棋盘：从「描边网格」改为「刻痕网格」

#### 布局构造（这段踩了三个坑，务必先读懂再改）

```css
.xq-board { display: flex; aspect-ratio: 8 / 9.75; padding: 7% 6% 8%; }
.xq-plane { position: relative; flex: 1 1 auto; min-width: 0; min-height: 0; }
.xq-plane > svg { position: absolute; inset: 0; width: 100%; height: 100%; }
```

**为什么是 flex，而不是更直观的百分比高度/绝对定位** —— 三条都是实测踩出来的：

| 写法 | 症状 | 实测数据 |
|---|---|---|
| `.xq-plane { height: 100% }` | 父元素高度来自 `aspect-ratio`、padding 又是百分比 → 循环依赖，浏览器退化成忽略 padding | 坐标面 282×274（比宽还矮），0 行棋子被上边框切掉半个 |
| `.xq-plane { position:absolute; inset:7% 6% 8% }` | 绝对定位的百分比偏移，解析基准是包含块的 padding box，和「棋盘外框」不是一回事 | 实测偏移 29.4px，而 CSS padding-top 是 23.2px，差 6.2px，照样被切 |
| `.xq-plane > svg { inset:0 }`（不写宽高） | SVG 是**替换元素**，有内禀比例，只给 inset 它会按 viewBox 自己算高度 | svg 292×328.6 vs 坐标面 292×373.7，矮了 45px，网格线与棋子整体错位 |
| **flex 撑满（当前）** | 无 | 坐标面 = 内容盒，偏移 `(23.2, 19.9)` 与 padding 完全一致；svg 与坐标面尺寸完全相同 |

#### 比例必须算，不能拍

坐标面宽 = `W × 0.88`，高 = `H × 0.85`，格距比 `X:Y = (0.88W/8) : (0.85H/9)`。
参考图实测 `X:Y = 1 : 1.085`，反解 `H/W = 1.085 × (0.88/0.85) × (9/8) = 1.2637`。

但推导值 `8 / 10.11` 实测只得到 `ratio = 1.125`（差 3.7%），说明百分比 padding 与 `aspect-ratio` 的交互有额外损耗。
**最终采用量出来的值 `8 / 9.75`**（实测 `ratio = 1.060`，误差 2.3%，肉眼看不出行距不匀）。
改 padding 或改棋盘宽度后必须重新量，不要相信推导值。

#### 刻痕效果

同一条线画两遍：深色（凹槽）下移 0.009，亮色（受光棱）留在原位。

```js
// xqGridSvg() 内
const d = parts.join('');
'<svg viewBox="-0.015 -0.015 8.03 9.03" preserveAspectRatio="none">' +
  '<g class="xq-groove">' + d + '</g>' +
  '<g class="xq-ridge">'  + d + '</g></svg>'
```

```css
.xq-groove { fill:none; stroke: var(--xq-groove);    stroke-width: 1.7; transform: translate(0, 0.009); }
.xq-ridge  { fill:none; stroke: var(--xq-groove-hi); stroke-width: 1; }
.xq-groove line, .xq-ridge line { vector-effect: non-scaling-stroke; }
```

> **坑**：颜色只能写在 CSS 里。写成 SVG 的 `stroke="var(--xq-groove)"` **表现属性**，Edge/Safari 解析不了变量会把 `stroke` 判成 `none` —— 整块棋盘变成白板，一条线都不剩。这个 bug 只在真机/浏览器里才暴露，静态检查发现不了。

### 5.3 棋子：三层圆盘

```css
.xq-p {
  position: absolute; width: 11.2%; aspect-ratio: 1;   /* 格距 ~12.5% 的 0.9 倍 */
  transform: translate(-50%, -50%);
  display: flex; align-items: center; justify-content: center;
  border-radius: 50%;
  font-size: var(--fs-lg); font-weight: 700;
  cursor: pointer;
  background:
    radial-gradient(circle at 34% 28%, var(--xq-coin-face) 0%, #ffdb9b 42%, var(--xq-coin-edge) 78%, var(--xq-coin-side) 100%);
  border: 1.5px solid var(--xq-coin-rim);
  box-shadow:
    0 2px 0 var(--xq-coin-side),                        /* 厚度 */
    0 3px 6px var(--xq-coin-shadow),                    /* 落地阴影 */
    inset 0 -2px 4px rgba(140, 96, 32, 0.35),           /* 内圈暗部 */
    inset 0 1px 2px rgba(255, 255, 255, 0.55);          /* 上缘高光 */
}
.xq-p::after {                                          /* 内圈刻线：参考图的「双圈」 */
  content: ''; position: absolute; inset: 9%;
  border-radius: 50%; border: 1px solid currentColor; opacity: 0.5;
}
.xq-p.red   { color: var(--xq-red-ink); }
.xq-p.black { color: var(--xq-black-ink); }
```

选中 / 上一步用**外发光环**而不是 `box-shadow` 覆盖（覆盖会吃掉厚度和阴影）：

```css
.xq-p.sel::before, .xq-p.last::before {
  content: ''; position: absolute; inset: -14%; border-radius: 50%;
  border: 2px solid var(--xq-ring, #ffcf5c);
  box-shadow: 0 0 8px rgba(255, 207, 92, 0.65);
}
.xq-p.last::before { border-color: color-mix(in srgb, var(--orange) 70%, transparent); box-shadow: none; }
```

### 5.5 操作行：从文字按钮改为「图标 + 标签」

参考图是 6 个「方底 + 金图标 + 下方标签」。残局模式下重排为 5 个，语义不变：

| 位置 | 图标 | 标签 | 绑定的既有函数 |
|---|---|---|---|
| 1 | 灯泡 | 提示 | `xqHint()` |
| 2 | 回退箭头 | 悔棋 | `xqUndo()` |
| 3 | 圆环 | 重摆 | `xqReset()` |
| 4 | 左箭头 | 上一关 | `xqLevel(-1)` |
| 5 | 右箭头 | 下一关 | `xqLevel(1)` |

新增了 4 个图标到 `ICONSET`：`undo` / `redo` / `prev` / `next`（`thought` 复用原有灯泡）。

**尺寸守铁律**：按钮本体 `min-height: 44px`，整行 `display: grid; grid-template-columns: repeat(5, 1fr); gap: 6px`。
在 375px 屏上（减去容器 32px 内边距、再减去区块内边距）单格宽约 62px > 44px ✓。

**为什么把 ‹ › 从顶部挪到操作行**：拇指自然活动的区域在屏幕下半部，顶部两侧是手机端最难按的位置之一。
原来的「上一关/下一关」在 `.xq-bar` 两端，手机上要换手或者挪动整只手；放进棋盘下方的操作行后就近可及。

### 5.7 响应式

| 断点 | 处理 |
|---|---|
| 默认（< 420px 手机） | 单列；棋盘满宽；操作行 5 等分；关卡圆点 26px |
| ≥ 560px | 棋盘 `max-width: 420px; margin-inline: auto` 居中，避免平板上棋盘被拉到 900px 宽导致棋子偏远 |
| ≥ 900px | 棋盘与信息区左右分栏（`grid-template-columns: 420px 1fr`） |

**手机优先的细节**（这几条是实际影响手感的）：
- 棋盘 `touch-action: manipulation` —— 去掉双击缩放 300ms 延迟
- `.xq-hit` 热区取 **16%**（格距 12.5%），相邻热区**互相重叠**：手指落在两格中间时，
  后渲染的那个赢，等价于吸附到最近交叉点。取刚好的 12.5% 在 375px 屏上只有 35px，
  低于 44px 下限，手指会频繁点空。实测 16% 在 375px 屏上约 44px。
- 棋子 `pointer-events: none`，落子只走 `.xq-hit` —— 保持原有的「棋子不挂 onclick」设计，避免同一次触摸双触发
- 去掉所有 `:hover` 依赖（手机没有 hover）
- 选中态必须**不需要 hover 就能看出来**：用 `::before` 外环 + 外发光，而不是覆盖 `box-shadow`
  （覆盖会把棋子「厚度 + 落地阴影」一起吃掉，子会瞬间变平）

#### 5.8.1 这些几何约束是被「变异测试」验过的

`chess-ui.test.js` 的 22 项断言不是「有没有写某行 CSS」，而是几何约束。为了确认它们
真能拦住回归（而不是写了一堆永远为真的断言），逐条施加了 15 处变异，每处单独改一处
CSS 再跑测试，**15/15 全部被捕获**：

| 变异 | 被哪条断言捕获 |
|---|---|
| 棋盘去掉 `display:flex` | 【1】board 必须 flex |
| `.xq-plane` 去掉 `flex:1` | 【1】plane 必须 flex:1 |
| 坐标面改回 `position:absolute` | 【1】plane 不得绝对定位 |
| SVG 去掉显式宽高 | 【2】svg 必须 width/height 100% |
| 网格色写回内联 `stroke="var()"` | 【3】不得用表现属性挂色 |
| 上边距 7% 收成 3% | 【4】上石边 > 半个棋子 |
| 棋子放大到 13% | 【5】棋子直径 < 格距 |
| `aspect-ratio` 凭感觉写 `8/9` | 【6】格距比容差 1.00~1.12 |
| 热区缩回 12.5% | 【7】热区 ≥44px 且 > 格距 |
| 操作按钮去掉 `min-height` | 【8】按钮 ≥44px |
| 棋子放开 `pointer-events` | 【10】`.xq-p` 必须让开指针 |
| 选中态改去覆盖 `box-shadow` | 【9】不得覆盖棋子阴影 |
| 难度行去掉 `flex-wrap` | 【11】窄屏兜底 |
| 操作行 `minmax(0,1fr)` 换回 `1fr` | 【11】窄屏兜底 |
| 难度块文字去掉 `ellipsis` 收口 | 【11】文字必须收口 |

变异测试过程中还揪出**测试自身的两个漏洞**，已一并修掉：

- 【6】容差原本是 `0.95~1.22`，`8/9` 算出来 0.966、`8/11` 算出来 1.181 都能蒙过去。
  收紧到 `1.00~1.12` 后，`aspect-ratio: 8/9` 这个「看起来差不多」的错误比例才被拦住。
- `.xq-p` 的 `pointer-events` 变异最初报「搜索串未命中」——替换根本没生效，
  「0 失败」是个假结论。修正锚点后确认该变异确实被捕获。
  **教训：变异测试必须先断言「变异真的施加了」，否则通过等于没测。**

#### 5.8.2 窄屏截图的坑（重要）

用 Edge headless 的 `--window-size=375,900` 截图**不能用来看窄屏有没有溢出**：
这个构建会把小于 ~500px 的窗口钳到 492px，于是「375px 的截图」其实是在**裁一张
492px 宽的版心**——看上去就像内容被右侧切掉了（`下一关` 整个消失、`三步杀` 断字），
但页面本身 `innerWidth=492`、`bodyW=482`，layout 完全正常。

实测同一份页面在不同窗口宽下：

| `--window-size` | 实际 `innerWidth` | 版心宽 |
|---|---|---|
| 375 | **492** | 482 |
| 390 | **492** | 482 |
| 768 | 744 | 734 |

**要量真实窄屏，用 `<iframe width="375">` 指定精确宽度**（iframe 不受该钳制），
或直接读 `innerWidth` 核对。窄窗截图只适合看「整体观感」，不适合判断溢出。

**换算备忘**
- 格距 = `100% / 8 = 12.5%`
- 棋子直径 = 格距 × 0.90 = `11.25%`（参考图实测 0.917，留 2% 手感余量避免相邻子黏连）
- 上边距下限 = 棋子直径 / 2 = `5.625%`（低于此 0 行棋子会被上边框切）
- 热区下限 = `44px / 屏宽`（375px 屏 → 11.7%，但热区是百分比宽度，取 16% 保险）
