## 一、一句话说清架构

```
你的浏览器（能拿到视频地址）
        ↓ 导出 JSON
    服务器（流式抽音频 → 转写 → 分析 → 入库）
```

**为什么必须这么分**：抖音对服务器做了风控（滑块验证），
服务器自己拿不到视频。你的浏览器是你自己的，早就过了验证。

**顺带说清一个常见疑问：能不能直接下音频？**
不能。抖音只给视频流地址（`mime_type=video_mp4`），人声和画面在同一条流里，
拿不到纯人声轨道。导出里那些 `.mp3` 是**背景音乐**，不是人说话的声音。

但**也不用把视频存下来**。ffmpeg 自己就是流式下载器：

```bash
ffmpeg -i <CDN地址> -vn -c:a aac -b:a 64k out.m4a
```

`-vn` 表示丢弃视频轨，音频读完就收工，**视频数据边读边丢、全程不落盘**。
实测 15 秒视频从「两轮 I/O」降到 **1.1 秒**，磁盘峰值从「视频大小」降到「只有音频」。

## 二、日常怎么用

### 第 1 步：采集（你的浏览器，约 5 分钟）

1. 打开抖音 → 点进要采的收藏夹
2. 右上角面板 → 点绿色 **「⏺ 开始采集」**
3. **往下滑，让每个视频都播一下**
   （只有播过的视频才有地址 —— 面板会实时显示「含播放地址 X 条」）
4. 滑到底 → 点 **「导出 N 条」** → 内容自动进剪贴板
5. **把内容粘给我**

> ⚠️ **地址有时效**（通常几小时）。采完尽快给我，别隔夜。

### 第 2 步：跑（我来做）

```bash
# 先看一遍要跑什么、花多少（不花钱）
python3 run_batch.py 导出.json --collection "对自己好" --dry-run

# 先跑 5 条看效果
python3 run_batch.py 导出.json --collection "对自己好" --limit 5

# 满意了再跑全部
python3 run_batch.py 导出.json --collection "对自己好"
```

**关键参数**：

| 参数 | 作用 |
|---|---|
| `--dry-run` | 只列表，不跑（零成本） |
| `--limit N` | 只跑前 N 条 |
| `--clip 300` | **只转写前 300 秒** —— 长视频试效果用，省钱利器 |
| `--summary-model 名字` | 换摘要模型（不重付 ASR） |
| `--force` | 已有转写也重跑（默认跳过） |

跑的时候我会告诉你：处理几条、跳过几条（已有转写）、预估花多少额度。

## 六、出问题怎么办

| 现象 | 原因 | 处理 |
|---|---|---|
| 下载失败「地址可能已过期」 | 采完放太久 | 重新采集 |
| 面板不出现 | 篡改猴没权限 | 见 `COOKIE-AND-KEY.md` 第一节 |
| 「含播放地址 0 条」 | 没播视频 | 往下滑，让视频真的播 |
| ASR 报 `SUCCESS_WITH_NO_VALID_FRAGMENT` | 音频里没人声 | 正常，跳过这条 |
| 「跳过 N 条（已有转写）」 | **这是好事** | 说明省钱了 |
