## 零、❗如果脚本不弹 —— 先按这个顺序查

> 2026-09-26 实测：用户踩了两个坑，**两个都不在脚本身上**。
> 排查顺序是「**先确认脚本有没有被注入，再谈注入了为什么没效果**」。

### 先问自己一句：我刚才手动点过篡改猴的什么东西吗

**篡改猴菜单里有一项是"删除该站点权限"，误点之后该站点会进篡改猴内部的黑名单。**
这种情况下**扩展级权限开到"所有站点"也没用** —— 篡改猴内部记录的用户拒绝优先级更高。

| 现象 | 层级 | 怎么修 |
|---|---|---|
| 菜单写「篡改猴没有访问此页面的权限」 | Edge 扩展权限 | 见下面 第 1 查 |
| 菜单写「网站访问权限：未允许此站点使用扩展」 | **篡改猴内部黑名单** | 见下面 第 2 查 |
| 同菜单里**其他脚本也都不跑** | 上面任一，是全局权限问题 | 不是单个脚本的锅 |

### 第 1 查：Edge 扩展权限（默认「单击时」）

点篡改猴图标，菜单里有这一行：

```
篡改猴没有访问此页面的权限
```

**有 → 就是这个问题：**

1. 地址栏输入 `edge://extensions/` 回车
2. 找到 **Tampermonkey** → 点**「详细信息」**
3. 往下找 **「站点访问权限」**
4. 从 **「单击时」** 改成 **「在所有站点上」**
5. **彻底关掉抖音标签页，重新打开**（刷新有时不重新申请权限）

### 第 2 查：篡改猴内部站点黑名单（右键菜单 → 网站访问权限）

右键篡改猴图标，看有没有：

```
网站访问权限
  未允许此站点使用扩展        ← 就是它
```

**有 → 是篡改猴内部把 douyin.com 拉黑了**（多半是误点过"删除该站点权限"）：

- 右键菜单 → **「网站访问权限」** → 再点一次，切成「允许此站点使用扩展」
- 或者：篡改猴「管理面板」→「设置」→ 把 **配置模式** 改成 **高级** →
  在「安全」里能看到站点黑白名单，把 douyin.com 从黑名单移除

### 第 3 查：脚本和面板

权限确实放开了之后：

1. **彻底关掉标签页重开**（不是 Ctrl+R —— 刷新有时不重新申请权限）
2. **篡改猴图标上有数字角标** = 当前页面有 N 个脚本在跑
3. 面板在**任何 douyin.com 页面**都该出现（不只收藏页）

### 第 4 查：面板在了但数字不动

看面板上的「**最近接口**」一栏 —— 这是专门为远程诊断做的：

| 最近接口显示 | 含义 |
|---|---|
| （暂无） | 页面还没发收藏夹请求 → 往下滚 |
| 有路径但不是 collect | 接口名和我猜的不一样 → **截图给我，我改匹配** |
| 有 collect 路径但数字不动 | 数据形态没认出来 → 截图给我，我改解析 |

都试过还是没有 → 截图给我（**要带上篡改猴图标和它的下拉菜单**）。

**顺便：控制台里那些红字不用管。** 比如
`imapi.douyin.com/.../get_conversation_list` 的 CORS 报错 ——
那是抖音自己的私信接口在报错，跟我们无关。

## 三、脚本干了什么（你可以自己核对）

脚本在 `docs/tools/douyin-favorites.user.js`，随便看。

| 它做 | 它**不**做 |
|---|---|
| ✅ 挂 XHR + fetch 两个钩子，把抖音页面**自己**调的收藏夹接口返回抄一份 | ❌ 不自己构造请求、不算签名 |
| ✅ 按 `aweme_id` 去重、只留有用字段 | ❌ 不上传任何数据到第三方 |
| ✅ 生成 JSON 下载到本地 | ❌ **不调用任何写接口**（不收藏/取消/点赞/评论） |
| ✅ 面板显示「最近接口」和钩子状态 | ❌ 不在页面上做任何视觉改动 |

**关键点：它不碰 cookie，不碰签名算法。**
抖音的反爬要求签名匹配**当前时刻的浏览器环境**，网上纯 Python 方案的
映射表停在 2024 年初（我实测过，见 `docs/COLLECTION-ACCESS.md`），早失效。
让浏览器自己算才是唯一稳的路。

**三道验证：**

```bash
cd docs/tools

# ① 基础逻辑：截获 → 去重 → 导出
node test-userscript.js douyin-favorites.user.js
# 实测输出：3 页 10 条（含 1 条重复）→ 导出 9 条 ✅

# ② v3 专项：分组识别 + 宽松匹配 + 面板必建
node test-userscript-v3.js douyin-favorites.user.js
# 实测输出：全部通过（12 项）✅

# ③ 真浏览器：面板在真实 Chromium 里到底建不建得出来
#    （v2 栽的就是这一关，假 DOM 测不到）
NODE_PATH="C:/Users/HXT/.workbuddy-ai/binaries/node/workspace/node_modules" \
  "C:/Users/HXT/.workbuddy-ai/binaries/node/versions/22.22.2-3/node.exe" \
  test-userscript-real.js douyin-favorites.user.js
# 实测输出：全部通过（10 项）✅
#   面板真出现在 DOM / 显示"4 个收藏夹分组" / XHR 钩子生效 /
#   不溢出 430x932 屏幕 / __nexusDyStat 可用

# ④ 只读性（应无输出）
grep -nE "method:\s*['\"](POST|PUT|DELETE)|\.open\(['\"](POST|PUT|DELETE)" \
  douyin-favorites.user.js
```

> ③ 那个测试干的事：起一个本地服务，把 `www.douyin.com` 劫持过去，
> 用真 Chromium 打开并注入脚本，然后让假页面自己发一次收藏夹请求 ——
> 断言面板真的出现在 DOM 里。**这就是"v2 为什么弹不出来"那个问题的回归测试。**

## 四、隐私交代

| 数据 | 我拿到之后 |
|---|---|
| 收藏夹列表（标题/链接/作者/时长） | 只用来挑出成长类视频。不发布、不评论、不点赞 |
| 视频音频（仅选中的几条） | 转文字用。**转写完立即删**，最多在服务器上存在几分钟 |
| 你的 cookie | **这个方案根本不需要 cookie** |

旧方案要 cookie，等于交出「以你身份登录」的凭据 ——
**能读收藏夹，也能删你的收藏**。篡改猴方案绕开了这个风险。
