### 关于「用你的 cookie 读收藏夹」—— 说明我的边界

你明确说「我可以给你 cookie」，我接受。但我要把话说清楚：

1. **cookie 是你自己的账号凭据**，我会：
   - 只存在服务器 `server/.env`（`chmod 600`，和现有 `AUTH_TOKEN` 同样待遇）
   - **绝不回显到聊天里**、绝不写进代码仓库、绝不传给任何第三方
   - 你随时可以改密码让 cookie 失效
2. **cookie 是有有效期的**（抖音通常几天到几周）。过期后需要你重新取一次。
   我会：
   - 在设置页做一个「cookie 状态」显示，过期前提醒
   - **不允许**因为过期就静默失败 —— 必须明确告诉你「该换 cookie 了」
3. **不伪造请求签名**去绕抖音风控。用 cookie 是「你授权我以你的身份访问」，
   和「破解签名」是两回事，后者我不做。

### 3.1 我在写代码时踩到并修掉的三个接口错误（2026-09-26）

第一版 `transcribe()` 我是凭印象写的，**三个地方都错**。查阿里云官方文档后逐条修正：

| # | 我原来写的 | 官方实际要求 | 不改会怎样 |
|---|---|---|---|
| 1 | 模型 `paraformer-realtime-v2` | **`paraformer-v2`** | realtime 是 WebSocket 流式模型，不接受文件 → 直接失败 |
| 2 | 音频用 `data:audio/m4a;base64,...` 直传 | **必须是公网 HTTP/HTTPS URL**，官方原文「不支持 Base64 编码或本地文件路径」 | 提交即被拒 → 直接失败 |
| 3 | header `X-DashScope-Async: disable` | **`: enable`**（且必填） | 异步任务提交被拒 → 直接失败 |

**第 2 条是设计级的**，不是改个字符串就行：音频必须公网可达，
所以要有个「临时音频托管」。我用的是项目里已有的同款模式
（`/dropimg/` 那种 token 路径 + nginx 静态托管 + 随机文件名），没新造轮子：

- 目录 `/var/www/asrtmp/`，nginx 路由 `/asrtmp/`（挂在 nexus.kotete.xyz）
- 文件名 `secrets.token_urlsafe(24)` 生成，不可猜测
- **转写完成（无论成败）立即 `unlink`** —— 它是公网可见的，多留一秒都是风险
- 仅 GET/HEAD；非音频扩展名 403；目录列表 403

#### nginx 这段被我写错两次，都留了注释钉住

| 错法 | 症状 | 真因 |
|---|---|---|
| 把白名单正则 `location ~` **嵌**在 `location /asrtmp/` 里 | `/asrtmp/x.m4a` 返回 **301** 跳到 `/asrtmp/x.m4a/` | 嵌套正则在 alias 下语义混乱，nginx 把它当目录 |
| 兜底用 `location ^~ /asrtmp/` | **合法音频也 403** | `^~` 匹配后**直接跳过正则求值**，白名单那条永远不生效 |

最终写成两条**平级** location：正则白名单在前、普通前缀 403 兜底在后，
靠 nginx「正则优先于前缀」的规则决定优先级。

实测 8 个用例（2026-09-26）：

| 请求 | 结果 |
|---|---|
| `/asrtmp/x.m4a` | ✅ 200，内容正确 |
| `/asrtmp/x.txt`（非音频） | ✅ 403 |
| `/asrtmp/x.m4a/`（带斜杠） | ✅ 403 |
| `/asrtmp/`（目录列表） | ✅ 403 |
| `/asrtmp/nope.m4a`（不存在） | ✅ 404 |
| `/asrtmp/%2e%2e%2fsecret.txt`（编码穿越） | ✅ 404 |
| POST / PUT 到音频 | ✅ 403 |

### 3.3 ASR 结果解析：优先用整段文本，不是分句拼接

官方返回的 `transcription_url` 指向的 JSON 里有两个可用字段：
`transcripts[].text`（完整识别文本）和 `transcripts[].sentences[].text`（分句）。
**优先用前者** —— 分句再拼会丢掉标点和跨句上下文，拼出来更差。
分句只作为兜底（`transcripts[].text` 缺失时）。

### 3.4 端点家族错配 —— 本次最贵的一个坑（2026-09-26 修复）

**症状：** 我原来一律把总结请求打到 `text-generation` 端点，
用户的 10 个模型里 **7 个返回 400**：

```
InvalidParameter: url error, please check url！
```

**这条报错是误导的。** 它跟 `url` 一个字的关系都没有。
实测证明：**同一个 url、同一个 payload，只换端点，就从 400 变 200。**

**真相是两个端点家族：**

| 端点家族 | 实测可用的模型（本 key） |
|---|---|
| `text-generation` | `glm-5.3`、`deepseek-v4-flash-0731`、`deepseek-v4-pro-0813` |
| `multimodal-generation` | `qwen3.8-flash`、`qwen3.8-max-0902`、`qwen3.8-27b`、`qwen3.8-2.4t-a95b`、`qwen3.7-flash-2026-07-15`、`deepseek-v4.1-flash`、`kimi-k3` |

**而且两个家族的响应体形状不同 —— 这才是真正的根因：**

| 家族 | `choices[0].message.content` 类型 |
|---|---|
| text-generation | **字符串** `"收到"` |
| multimodal-generation | **列表** `[{"text": "收到"}]` |

我原来的解析代码只处理字符串，遇到 multimodal 的列表拿不到内容。

**修法（不是改字符串，是改设计）：**

1. `ENDPOINT_HINTS` 登记实测确认的「模型 → 端点」映射
2. **未登记的模型自动两端点探测**，试通就写缓存 —— 不靠我猜
3. `_pick_content()` 统一两种响应体形状（带注释钉住，防被"简化"掉）
4. `--list-models` 现在会报出每个模型走哪个端点

**顺带修掉域名问题：** 控制台给的专属域名
`https://ws-01q7948czi100mb.cn-beijing.maas.aliyuncs.com/api/v1`
对本 key **10/10 全部 403 `Endpoint.AccessDenied`**；
换回公开域名 `https://dashscope.aliyuncs.com/api/v1` 后 **10/10 可用**。
所以 `DASHSCOPE_BASE` 建议留空。

**测试覆盖：** `test_summarize.py` 从 16 项扩到 **27 项**，新增覆盖
两种响应体形状、端点自动探测与缓存、「url error」的误报识别、
`content` 为 `None`/空列表等边界。全部通过。

## 附：ASR 方案选型 —— SoundWise.ai 的实测评估

用户提出用 SoundWise.ai（声称「永久免费、无限制、本地处理」）替代付费 ASR。
**我去扒了它的前端代码验证，不是听它宣传。**

### 它是真的本地推理 —— 技术上确认

从 `soundwise.ai/_nuxt/DpBCSbZH.js` 里扒出的原文：

```js
models: [
  {name: "Fast",     label: "base",
   key: "onnx-community/whisper-base",            size: 206},
  {name: "Accurate", label: "large-v3-turbo",
   key: "onnx-community/whisper-large-v3-turbo",  size: 586}
]
```

- 用的是 **`onnx-community/whisper-*`** 系列（HuggingFace 上的 ONNX 量化版 Whisper）
- 走 **ONNX Runtime WebAssembly**（`ort.` 在 bundle 里出现 781 次）
- 模型 **206 MB / 586 MB 是拉到浏览器里跑的**，体积对得上
- 页面上打的是 `FREE` + `LOCAL` 徽标

**它不是"骗人的免费"，是真的用你的设备算力换免费额度。**

### 但对你的场景，有两个否决级问题

**① 手机上高精度那一档被锁住了 —— 直接违背手机端铁律**

源码里 `whisper-accurate`（`large-v3-turbo`）那一档带着：

```js
class: U(["model-option", { selected: ..., "mobile-locked": g.value }])
```

`mobile-locked`。也就是说**手机上只能用 `base` 那个 206 MB 的小模型**。
而 `base` 对中文口播的识别质量明显不如 Paraformer-v2。

你的铁律是「一切改动以手机端感受为主」——
一个「手机端只能跑低配档」的方案，从定位上就不合适。

**② 免费版 = 逐个手动上传，无法放进流水线**

免费版是本地跑，意味着：必须开浏览器、必须保持页面常开、
**不能由服务器调用**（服务器上没有"你的浏览器"）。

我们要做的是「每天自动挑 2 条已经分析好的视频推给你看」。
这需要**服务端无人值守批处理**。SoundWise 免费版做不到。

（它的专业版有云端处理，能 1 小时音频压到 30 秒 —— 但那是付费的，
付费就失去了"免费"这个选它的唯一理由。）

### 结论：不作为主方案，但有一个真正好用的地方

| 用途 | 用哪个 | 理由 |
|---|---|---|
| 服务端批量转写 | ✅ **Paraformer-v2** | 可自动化、中文强、10h/月免费够用（见 §3.6 成本） |
| 偶尔手动转个录音 | ✅ SoundWise.ai | 真免费、真本地、不传文件，隐私最好 |

**最优解是「本地优先 + 云端 fallback」**，但免费版只有本地档，
凑不成 fallback。所以现阶段：**主线继续用 Paraformer**。

> 值得记一笔：它"本地处理不传文件"这个点在**隐私**上确实优于我们现在的方案
> —— 我们为了满足 Paraformer「必须公网 URL」的要求，
> 音频会在 `/asrtmp/` 短暂地对公网可见（随机文件名 + 转写完立即删）。
> 这个风险是可以接受的（内容本身是公开的抖音视频），但如果哪天要转**私密录音**，
> 应该用 SoundWise 那种本地方案，不该用这条流水线。

### 关于「百炼 ASR 是不是要钱」

用户的截图里有一张写着「这个貌似要钱 没有免费额度」。

**核对结果：Paraformer 有免费额度，是 10 小时/月，每月 1 日重置。**
（这是官方文档里明确写的一个例外 —— 文本模型是「一次性 90 天」，
ASR 是「每月重置」，两者规则不同。）

用户看到的"要钱"提示，很可能是控制台上**别的**语音产品
（比如语音合成 TTS、或实时语音识别），不是 Paraformer 文件转写。
本项目只用文件转写这条线。

## 六、风险与诚实交代

| 风险 | 说明 | 应对 |
|---|---|---|
| cookie 会过期 | 抖音 cookie 有效期通常几天~几周 | 做状态检测 + 过期提醒，不静默失败 |
| 抖音改风控 | yt-dlp 可能某天失效 | 用官方 extractor，社区会更新；失效时明确报错而非错数据 |
| ~~ASR 免费额度不确定~~ | ✅ **已查证**：Paraformer **10 小时/月**，每月 1 日重置 | 见下方「成本测算」 |
| 批量下载可能触发风控 | 短时间大量请求 | 加限速 + 串行/小并发，分批跑 |
| 摘要是 AI 生成的，可能有错 | LLM 会幻觉 | 每条都附「看原片」链接，你可核对 |
| **意外扣费** | 超出免费额度会按 0.6 元/小时计费 | **已做成本闸门**：本地记账 + 跨月归零 + 超预算拒跑 |

### 成本测算（2026-09-26 查证阿里云官方文档）

| 模型 | 免费额度 | 有效期 | 超出后 |
|---|---|---|---|
| Paraformer-V2 | **10 小时/月** | **每月 1 日 0 点重置** | 0.6 元/小时 |
| qwen-plus | 100 万 Token | 90 天，不续发 | 入 0.8 / 出 2.0 元每百万 Token |

**100 条视频（平均 2 分钟）**：

| 项 | 用量 | 占免费额度 |
|---|---|---|
| ASR | 3.3 小时 | 33%（且月月重置） |
| LLM | 13.5 万 Token | 13.5% |
| **合计** | — | **0 元** |

即使平均 5 分钟（8.3 小时）仍在免费额度内。

### 成本闸门（防止「跑完才发现扣钱」）

实现在 `server/tools/douyin_pipeline.py`：

| 机制 | 作用 |
|---|---|
| 按**官方返回的计费时长**记账（`usage.duration`） | 不靠文件大小估算，误差会算错钱 |
| 账本记月份，跨月读时归零 | 对应官方额度重置 |
| 批量前预估并拦截 | 超预算**连第一条都不跑** |
| 每次运行打印用量 | 你随时知道还剩多少 |

默认预算 = 免费额度。想超额需**显式**放宽 `--budget-seconds`。
另建议在控制台开启 **「免费额度用完即停」**（云端双保险）。

14 项计量测试见 `server/tools/test_usage.py`。
